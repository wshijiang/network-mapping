# 操作系统线索与资产系统推断

[功能指南](FEATURES.md) · [开发与维护](OS_DETECTION_DEVELOPMENT.md)

扫描节点采集服务响应，服务端根据已有握手信息推断系统，无需在目标机器安装程序。
该功能不会额外扫描端口，也不会在浏览器中连接目标。

## 查看结果

在任务详情、资产端口列表和搜索结果中查看“系统线索”；资产详情的“推测操作系统”汇总
当前用户可见的端口证据。点击结果可以展开协议、端口、命中字段、返回片段和证据时间。

| 显示状态 | 含义 |
| --- | --- |
| 识别中 | 服务证据已到达，后台尚未完成处理；稍后刷新 |
| Windows、Linux 等 | 返回特征支持相应系统判断；仍属于推断 |
| 未知 | 已处理，但返回字段不足以判断系统 |
| 证据冲突 | 不同返回特征指向不同系统，应结合各端口证据判断 |
| 暂无识别结果 | 仅有端口观察、旧数据尚未回填，或服务端版本尚未提供结果 |

“证据可能过期”表示证据早于最近端口观察，或者已经超过 30 天。再次发现开放端口不会
刷新系统证据时间；资产级推断不使用超过 30 天的证据。未再次发现端口不等于端口已关闭。

## 判断依据与限制

当前读取 SSH 标识、HTTP/HTTPS 的 `Server` 响应头，以及 SMB/RDP 返回的明确系统字段。
FTP、SMTP 中的明确系统标识可作为补充。支持 Windows、Linux、BSD、macOS 和宽泛的 Unix
类别；Ubuntu、Debian、CentOS、FreeBSD、OpenBSD、NetBSD 的明确标识可显示发行版线索。

普通 OpenSSH、nginx、Apache 或 Samba 名称不会直接产生系统结论，SMB/RDP 连接成功也不
代表 Windows。SSH 软件包后缀、IIS 版本、协议版本和 NTLM 构建字段不会被直接转换为系统
发行版本；只有明确的 `native_os` / `server_os` 文案才可能提供服务环境版本。

服务环境线索与宿主机推断分开展示。容器、代理、端口转发及多个后端可能产生不同系统
特征；同一 IP 在不同内网中也可能对应不同设备。系统相冲突时保留冲突，多个扫描视角的
汇总不会仅凭样本提高到高置信度。资产摘要不推断宿主机的精确版本。

置信度是规则分级，不是准确率或概率。相同协议、端口中的重复字段不会重复增加支持度；
高置信度要求独立协议的一致线索。未知结果仍是有效结果。

## 搜索与导出

搜索条件针对同一个端点的服务环境线索，`service.os.*` 是 `os.*` 的同义写法：

```text
os.family = windows
os.family = linux AND os.distribution = ubuntu
os.status = conflict
os.confidence = high AND os.score >= 60
has_endpoint(os.family = windows) AND has_endpoint(port = 445)
```

可用字段：`os.family`、`os.distribution`、`os.version`、`os.confidence`、`os.status`、
`os.score`。`score` 范围为 0–100，仅是规则得分；查询不会扩大扫描范围。
搜索页 CSV 包含系统家族、发行版、版本、状态、置信度、判断对象、证据时间和过期标识。

外部 API 需要在应用字段白名单中批准 `os`，之后才能返回摘要或使用 `os.*` 搜索条件。
外部摘要不包含原始证据片段、观察索引引用或候选明细，已有应用的字段权限不会自动增加。

## 升级与排障

先升级服务端，再升级前端及扫描器。服务端启动会添加任务队列表和 ES 投影字段映射，
不改写历史原始观察。完成资产发布后异步识别，扫描成功不等于系统识别已经完成。

历史成功执行会在后台分批回填；新规则版本会触发重新计算。原始数据已经被清理、字段
没有采集或旧响应已经被截断时，回填无法恢复缺失信息，需要重新执行服务识别任务。
较新的扫描器在超大握手被截断时会尽量保留小型系统字段，但仍遵守原有结果大小限制。

长时间显示“识别中”时，管理员检查 `OsDetectionWorkerError`、`OsDetectionPageCompleted`
日志以及 PostgreSQL `os_detection_outbox` 的 `last_error`、`available_at`、租约和完成时间。
处理只依赖已有证据，无需重启扫描器；失败任务会退避重试。
