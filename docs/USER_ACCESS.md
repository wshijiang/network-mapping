# 用户角色与权限管理

在控制台侧栏打开 **用户管理**。Web 可以创建普通、只读和审计账号，并编辑这三类账号的授权。初始管理员由服务端初始化，新增管理员使用受控的本地 CLI。Web 和 CLI 共用授权校验、版本检查和变更审计。

| 角色 | 可在用户管理中授予的操作 |
| --- | --- |
| 管理员 | 管理账号、扫描器、系统设置及业务数据。敏感操作会要求再次验证身份。 |
| 普通用户 | 读取本人任务、结果和统计，创建扫描，取消或重试本人任务，导出本人结果。 |
| 只读用户 | 读取本人任务、结果和统计，可单独授予结果导出。 |
| 审计用户 | 读取指定类别的审计事件，可单独授予审计导出。 |

所有角色都能管理自己的密码、登录白名单和个人资料。审计用户看到的是事件标识、操作者、动作、结果以及权限变更的角色和操作摘要。来源 IP、请求路径、原始事件元数据和账号授权范围只在管理员审计视图中显示。

## 通过 Web 配置

1. 在 **用户管理** 创建账号。新建的普通、只读和审计账号默认只有个人账号权限。
2. 在用户行选择 **编辑权限**。选择角色、允许的操作与适用范围。期限留空表示长期授权。
3. 填写变更原因并保存。如弹出重新验证，输入自己的当前密码和已启用的 TOTP 验证码。近期验证在当前会话中有效五分钟。
4. 切换角色会使目标用户的会话失效。并发编辑时，后提交的旧版本会提示重新加载。

### 扫描和审计范围

扫描创建权限要求至少一个已存在的扫描器、一种扫描模式和一个目标 CIDR 或域名。显式授权用户须在创建时选择获授权的节点。目标 CIDR 必须完整落在授权网段内，域名条目匹配本身及以点分隔的子域。节点列表只提供选择所需的状态和能力。

受支持的模式为 `port_only`、`service_inventory`、`vulnerability_scan`、`udp_inventory` 和 `dns_records`。旧模式名 `legacy` 按 `port_only` 保存和执行。显式授权的 DNS 任务使用节点系统解析器，单独执行 DNS 记录查询。自定义解析器、DNS 派生端口扫描和自动或全部节点分配保留在现有管理员与兼容路径。授权可限制最高优先级、允许的端口范围、单任务目标数和端口数、未完成任务数以及滚动 24 小时内的任务数。

审计类别按完整名称匹配，例如 `user_security`、`authorization`、`authentication`、`task`、`scanner`。类别过滤同时适用于列表、详情和 CSV 导出。审计导出需要近期验证。

## 通过 CLI 配置

在服务端机器上使用有权读取服务端配置、访问数据库的本地操作系统账号。先读取当前授权版本，再提交完整的新授权。例如：

```sh
network_mapping_server --config config.toml user access show alice
network_mapping_server --config config.toml user access set alice \
  --role read-only --expected-version 0 --policy alice-access.json \
  --reason '调整为结果只读'
```

`--expected-version` 使用 `show` 返回的 `version`，更新后该值递增。`access set` 接受 `user`、`read-only` 和 `auditor`。例如，只读授权文件可写为：

```json
{
  "permissions": ["read_results"],
  "expires_at": null
}
```

普通用户的扫描授权示例。部署时请使用实际获授权的范围与节点 ID：

```json
{
  "permissions": ["read_results", "create_scan", "cancel_scan"],
  "target_cidrs": ["192.0.2.0/24"],
  "domains": [],
  "scanners": ["019a6500-38e0-7a00-8000-000000000001"],
  "profiles": ["port_only"],
  "max_priority": 1,
  "max_targets": 256,
  "max_ports": 20,
  "port_ranges": ["80", "443", "8000-8010"],
  "max_active_tasks": 5,
  "tasks_per_day": 25
}
```

使用 `read_audit`、`export_audit` 和 `audit_categories` 配置审计账号。业务结果导出使用 `export_results`。重试使用 `retry_scan`，同时需要 `create_scan`。用空 `permissions` 数组清空业务授权。配置到期时间时使用 RFC3339，例如 `2027-01-01T00:00:00+08:00`。原因会写入审计记录，请填写业务原因并避免粘贴凭据。

更多创建账号、会话和凭据命令见[用户管理 CLI](USER_MANAGEMENT_CLI.md)。

## 升级及撤权

先升级服务端，再部署配套控制台。老普通账号在首次显式配置前保留兼容模式。兼容期间全局节点详情和系统监控仍需要管理员权限。逐个确认业务职责后通过 Web 或 CLI 应用显式授权。首次保存时已有的开放平台凭据会被撤销，开放平台委派会移除。显式授权账户的扫描通过 Web 控制台创建，搜索只返回结果，不会触发自动扫描。其业务数据读取范围为本人所有的数据。

每次权限更新会更换授权版本。旧版本的排队任务会被取消，运行任务在心跳时停止续租并收到取消信号。授权到期也会停止调度。需要重新执行时，使用当前权限创建新任务。开放平台任务由原应用通过开放 API 重试。

升级前应核对普通账号历史创建及注册的扫描器，以及原任务属于开放平台、重试记录却无应用关联的未完成任务。数据库迁移保留已有账号和历史记录。
